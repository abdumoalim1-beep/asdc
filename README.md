# asdc — منصة أتمتة المستندات المتكررة

مساعد شخصي بمحادثة عربية حرة (مو مصنّف أوامر): يدير عملاءك ومنتجاتك ومؤثريك،
ويولّد مستندات من قوالب Word حقيقية، عبر أدوات (tool calling) يستدعيها بس لما
يحتاج فعليًا ينفّذ شي. كل مستخدم جديد يفتح النظام يحصل على **مساحة عمل جديدة
تمامًا من الصفر**، ويبدأ بمحادثة مباشرة يفهم منها النظام تفاصيل نشاطه ويستقبل
أول قوالبه المرفوعة.

## المعمارية

النظام مبني بطبقتين مستقلتين عن بعض:

1. **طبقة الأمان (لا تخترع بيانات، لا تنفّذ بدون تحقق)** — `store.py` / `templates.py`
   / `docx_template.py` / `validator.py` / `executor.py`. هذي الطبقة ثابتة، لا
   تعرف ولا تهتم كيف وصلها قرار التنفيذ.
2. **طبقة الوصول للقرار** — كيف يتحول كلام المستخدم لاستدعاء فعلي:
   - **الحالية (المنصة/الويب):** مساعد محادثة حر بأدوات (`agent.py`) — يتكلم
     بحرية كاملة، ويستدعي أداة (`add_entity` / `update_field` /
     `generate_document` / `query_entities`) بس لما يحتاج فعليًا يلمس بيانات.
     كل استدعاء يمر عبر طبقة الأمان (1) بلا أي تعديل عليها.
   - **القديمة (لا تزال موجودة، CLI فقط):** مصنّف نية واحدة لكل رسالة
     (`schema.py` / `llm_client.py` / `cli.py`) — أول نسخة من المشروع، الآن
     مو الواجهة الأساسية، لكن باقية شغّالة ومُختبرة (`register_template.py`
     يستخدم نفس أسلوبها للاستخراج الحرفي من نصوص القوالب).

## البنية

```
prompts/
  assistant_system_prompt.txt  شخصية المساعد الحالي + قواعد الأدوات + سلوك الإعداد الأولي
  system_prompt.txt            نص المصنّف القديم (يستخدمه cli.py فقط الآن)
  template_field_detection_prompt.txt  استخراج حقول قالب حرفيًا (يستخدمه register_template.py)

data/
  workspaces/<id>/  entities.json / templates.json / conversation.json / templates/ / documents/
                     — كل مساحة عمل معزولة تمامًا عن غيرها، تُنشأ فاضية بالكامل
  workspace_entities.json, available_templates.json  بيانات المسار القديم (cli.py) فقط

src/asdc/
  store.py / templates.py / docx_template.py   — قاعدة الكيانات، توليد المستندات
                                                  (نسخة جديدة دومًا للموقّع)، فهم قوالب Word
  validator.py / executor.py    — طبقة الأمان: تحقق قبل أي تنفيذ، ثابتة بين المسارين
  workspace.py    — عزل كل مساحة عمل (WorkspaceRegistry): إنشاء، تحميل، محادثة محفوظة
  agent.py        — مساعد المحادثة الحالي: تعريف الأدوات، حلقة tool-calling،
                     يحوّل كل استدعاء أداة لنفس validator/executor بدون تعديل عليهم
  register_template.py  تسجيل ملف .docx مرفوع كقالب (استخراج {{}} أو اقتراح تلقائي)
  server.py       FastAPI: POST /api/workspaces، GET /api/workspaces/{id}/state،
                   POST /api/workspaces/{id}/chat، POST /api/workspaces/{id}/templates/upload
  schema.py / llm_client.py / cli.py   المسار القديم (مصنّف نية واحدة)، REPL طرفية فقط

web/index.html    واجهة المحادثة (RTL): تنشئ مساحة عمل جديدة تلقائيًا لأول زيارة
                   (localStorage)، الملفات والإحصاءات حية من الـ API، ما فيه ردود مبرمجة
tests/            لكل طبقة + agent.py (حلقة tool-calling برد نموذج مزيّف) + server.py
                   (workspace-scoped، بدون لمس بيانات المستودع الحقيقية)
```

## تشغيل المنصة (الواجهة الأساسية)

المشروع مبني بـ`src/` layout — لازم يُثبَّت كـ package محلي (`pip install -e .`)
حتى `import asdc` يشتغل بدون ما تحتاج تضبط `PYTHONPATH` يدويًا كل جلسة طرفية.

**macOS / Linux:**
```bash
pip install -e .
export OPENAI_API_KEY=sk-...
export ASDC_MODEL=gpt-5-mini   # اختياري، هذا الافتراضي، ويدعم tool calling
uvicorn asdc.server:app --reload
```

**Windows (PowerShell):**
```powershell
pip install -e .
$env:OPENAI_API_KEY = "sk-..."
uvicorn asdc.server:app --reload
```

**Windows (Command Prompt):**
```cmd
pip install -e .
set OPENAI_API_KEY=sk-...
uvicorn asdc.server:app --reload
```

لو `uvicorn` طلع "not recognized"، جرب `python -m uvicorn asdc.server:app --reload`
بدالها. متغيرات البيئة (`set`/`$env:`/`export`) تنضبط للجلسة الحالية بس — أعد
ضبطها كل مرة تفتح ترمنال جديد.

افتح `http://127.0.0.1:8000`. أول زيارة تنشئ مساحة عمل جديدة فاضية تمامًا
تلقائيًا (`POST /api/workspaces`)، والمساعد يرحّب ويطلب منك تعرّفه بنشاطك —
تذكر له عميلك أو منتجك الأول بجملة عادية، أو ترفع أول قالب Word تستخدمه عبر
زر الدبوس. كل شي بعد كذا (إحصاءات، ملفات، محادثة) حي من `/api/workspaces/{id}/*`
الحقيقي، بدون أي بيانات وهمية أو ردود مبرمجة سلفًا.

**حفظ المحادثة:** كل مساحة عمل تحفظ محادثتها كاملة (`conversation.json`) —
لو رجعت لنفس المتصفح، `localStorage` يتذكر مساحة عملك وتكمل من وين وقفت.

**نشر المنصة على استضافة حقيقية:** التخزين حاليًا ملفات محلية (`data/workspaces/`)،
فمنصات serverless بحتة (زي Vercel functions) ما تصلح مباشرة — القرص عندها غير
دائم بين الطلبات. تشتغل بدون أي تعديل على منصات فيها قرص/عملية دائمة (Render,
Railway, Fly.io, أو أي VPS): شغّل نفس أمر `uvicorn` كخدمة دائمة.

## تشغيل المسار القديم (CLI، مصنّف نية واحدة)

لسا شغّال، لأغراض المقارنة والاختبار، على بيانات تجريبية ثابتة (`data/`):

```bash
pip install -e .
export OPENAI_API_KEY=sk-...
python -m asdc.cli
python -m asdc.cli --batch تعديلات.txt   # قائمة تعديلات دفعة وحدة
```

## رفع قالب Word (من الـ CLI مباشرة، بدون المرور بالمنصة)

```bash
python -m asdc.register_template مسار/العقد.docx "عقد تقديم خدمات" عميل           # فيه {{}} صريحة
python -m asdc.register_template مسار/العقد_القديم.docx "عقد تقديم خدمات" عميل --auto  # بدون {{}}، اقتراح تلقائي
```

القالب المسجّل — من الـ CLI أو من زر الرفع بالمنصة — يطلع منه ملف `.docx`
حقيقي بنفس تنسيق الأصل عند `generate_document`، معبّى من بيانات الكيان
الحقيقية، مو نص عادي.

## الاختبارات

```bash
pip install -r requirements-dev.txt
pytest
```

67 اختبار، بدون أي استدعاء API خارجي — `agent.py` و`llm_client.py` كلاهما
يُختبران بدالة نموذج مزيّفة (fake model call) تُحاكي ردود حقيقية (بما فيها
استدعاءات أدوات متعددة بنفس الدورة، وردود فاشلة). `tests/conftest.py` ينسخ
بيانات `data/` لمسار مؤقت قبل كل اختبار — أي اختبار يستدعي `.save()` ما يقدر
يلمس ملفات المستودع الحقيقية.

## القواعد المطبَّقة فعليًا في الكود (ثابتة بين المسارين القديم والجديد)

- **لا اختراع بيانات:** `docx_template.build_rendered_docx` يترك أي placeholder
  ناقص كما هو ويُرجع اسمه؛ `executor.execute` يرفض توليد المستند عندها بدلًا
  من تعبئته بقيمة افتراضية.
- **معرّف كيان غير موجود = رفض تنفيذ:** `validator.validate` يتحقق أن
  `matched_entity_id`/`entity_id` موجود فعليًا قبل أي تحديث أو توليد مستند —
  سواء جاء من تصنيف نية أو من استدعاء أداة.
- **لا تحديث جماعي ضمني:** `update_field` بدون معرّف كيان محدد صراحة يُرفض،
  بدل تخمين الكيانات المستهدفة.
- **القوالب فقط من القائمة المتاحة فعليًا** لمساحة العمل، وترفض تطبيق قالب
  على نوع كيان مختلف عن `applies_to` الخاص به.
- **عدم تعديل المستندات الموقّعة:** أي مستند جديد لكيان عنده وثيقة "موقّعة"
  أو "مُرسلة" ينشئ نسخة منفصلة، ولا يلمس القديمة إطلاقًا.
- **لا تنفيذ بدون تحقق:** `executor.execute` يستدعي `validator.validate`
  داخليًا ويرفع `ExecutionRefused` عند أي فشل — في المسار الجديد، فشل هذا يرجع
  للنموذج كـ `ok: false` بدل ما يوصل للمستخدم كخطأ برمجي.

## ملاحظات

- **ليش صار فيه مساران:** المشروع بدأ كمصنّف نية واحدة (`prompts/system_prompt.txt`)
  بناءً على تصميم أولي، ثم تبيّن إنه يحصر المساعد بصندوق ضيق ويمنعه يتصرف
  كمساعد شخصي حقيقي (ترحيب، شرح، فهم سياق). المسار الجديد (`agent.py` +
  `prompts/assistant_system_prompt.txt`) يحل هذا بفصل "الكلام الحر" عن
  "الإجراء المتحقق منه"، بدل ما يجبر كل رسالة تتحول لنية واحدة جامدة.
  طبقة الأمان (validator/executor) ما اتغيّرت — نفسها بالضبط تُستدعى من
  المسارين.
- **حدود معروفة حاليًا (مو مبنية بعد):** استيراد Excel/CSV، صيغ PDF/PowerPoint
  (docx فقط الآن)، التحديث التسلسلي التلقائي لمستندات سابقة عند تغيير بيانات
  المصدر (تحديث حقل يحدّث الكيان نفسه، ما يعيد توليد مستندات قديمة تلقائيًا)،
  ومبدّل بين عدة مساحات عمل موجودة (كل زيارة جديدة بدون `localStorage` تنشئ
  مساحة عمل جديدة، ما فيه قائمة "مساحاتي" للتنقل بينها بعد).
